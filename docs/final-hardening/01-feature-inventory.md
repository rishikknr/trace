# Feature inventory and control coverage

Audit date: 11 November 2026, Asia/Kolkata. This inventory describes the current source, rather than treating the previous verification reports as evidence of a new run. The original [Step 09 contracts](../authentication-and-authorization.md), [Step 10 API](../step10/api.md), and [page specifications](../ui-ux/page-design-specifications.md) remain the detailed references.

## How to use the inventory

[evidence/control-inventory.tsv](evidence/control-inventory.tsv) indexes every JSX control declaration under `frontend/src`: file, current line, enclosing function, control type, accessible label/name where static, and attributes/handler source. It currently contains 379 declarations, including shared and retained legacy components. Runtime row buttons/options repeat their declaration; 379 is not a count of unique visible buttons. Regenerate after source changes with `python3 docs/final-hardening/generate-inventory.py`.

The table below supplies the API-to-storage join for those controls. Common request/session/RLS behavior is in [architecture](02-architecture-and-data-flow.md). All primary browse lists use `BrowseController → BrowseService → BrowseRepository`, a tenant transaction, stable ID tie-breaks, and 25-row UI pages / 100-row API maximum. Inputs without a request handler participate in their enclosing form or native disclosure, rather than representing disconnected actions. The source index is an audit aid; observed browser coverage is separately recorded in [test results](10-end-to-end-test-results.md).

## Verification boundaries

The browser suite uses real React → Spring → PostgreSQL and real Python parsers, with an explicitly labeled GitHub acquisition simulation. Backend HTTP/SQL tests exercise viewer, editor, owner, organization administrator, platform administrator, new account and multi-organization contexts. Component tests cover inputs, selectors, pagination, validation, errors, modal cancellation, request epochs and comparison races. No live provider or screen-reader conformance is inferred from these tests.

`features/metadata-import/ImportPage.tsx` is a retained earlier implementation, not a route mounted by the current `TraceApp`. Its declarations remain in the source index; current Snowflake CSV functionality is exposed through Import Center. There is no mocked replacement route.
