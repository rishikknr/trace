# Connector reliability and evidence

The [connector guide](../step10/connectors-and-imports.md) documents configuration/credential fields and provider boundaries. Existing Snowflake, S3, GitHub SQL, Power BI, MANUAL and FILE_IMPORT workflows remain. This pass contacted no live vendor. The reserved acceptance GitHub repository is an explicitly labeled transport simulation.

Acquisition schemaVersion 1 now carries `snapshotComplete` and an opaque SHA-256 `inventoryScope`. The scope covers provider/configuration identity and selection, excluding inventory size limits and optional view-definition enrichment. Old processors without the new completeness flag are conservatively partial; incompatible schema versions fail with PROCESSOR_INVALID_RESPONSE. A complete flag requires a valid scope. Uploads cannot claim authoritative live inventory: the server overwrites their acquisition provenance and does not honor their completeness for retirement.

Queue COMPLETED means a complete acquisition preview exists; PARTIALLY_COMPLETED means acquisition scope was not established complete. Neither means canonical metadata has committed. Warnings can be informational, so warning text no longer controls completeness. Config/credentials changed after queueing are rejected before acquisition/publication. Test callbacks similarly reject stale settings. Cancellation fences preview publication; retry preserves old run/attempt history.

Network/provider simulations cover each adapter's success, empty, partial, credentials, permission, throttling, timeout, malformed response and secret-redaction paths. The actual Java queue and Python parsing are exercised separately. Provider test errors persist safe status/reason rather than generic success. See [test evidence](10-end-to-end-test-results.md).

Remaining boundaries are deliberate: S3 versions/custom metadata/body schema inspection, Snowflake execution/query-history lineage, full GitHub macro/dynamic SQL resolution, Power BI XMLA/admin scanning/DAX/visual extraction are not represented as implemented live features. No external datasets or NovaMart fixtures were deployed.
